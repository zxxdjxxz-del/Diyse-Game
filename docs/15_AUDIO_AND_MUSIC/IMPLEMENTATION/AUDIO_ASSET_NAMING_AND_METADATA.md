# Diyse — Audio Asset Naming & Metadata

**Status:** ACTIVE AUDIO IMPLEMENTATION REQUIREMENTS  
**Parent authority:** `../AUDIO_AUTHORITY_MASTER.md`

Future production assets should use stable semantic naming.

Useful fields:
- asset ID;
- category;
- cue/SFX role;
- loop start/end if applicable;
- loudness/mastering version;
- source/license metadata where required;
- current/retired status.

## Do not use obsolete canon as new asset naming
Avoid creating new active assets named after:
- Heartlands
- Highlands
- Edgelands
- Blackstone
- Resource Face
- Acuity Face
- Change Face
- Last Measure

unless the file is explicitly archival research.

## Prototype naming
Development renders should visibly indicate:
- TEST
- SAMPLE
- RND
- PROTOTYPE
- NOT_CANON

where needed.

Do not overwrite the only research/source master with a compressed runtime export.
